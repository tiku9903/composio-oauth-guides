How the guides are made

Every guide answers one question: what stands between you and letting any of your users connect this app through your agent?

Three objects people mix up

  • The OAuth app is registered once with the provider. It has a client ID and secret, redirect URIs and allowed scopes, and its name is what your users see on the consent screen. This is the thing that may need approval.
  • Your auth config in Composio says which OAuth app and scopes your integration uses. Composio provides a managed OAuth app for some toolkits; for the rest you bring your own and register Composio's callback, {{ REDIRECT_URI }}, as the redirect URI.
  • A connection is one end user authorizing their account. One OAuth app serves all of them. Approval problems show up here: an "unverified app" screen, a 100-user cap, or an admin who must approve the app.

"Tested live" can only cite a probe the agent ran. "From official source" must cite a fetched page; if every cited page is a forum or blog, it drops to "uncertain". Review timelines are usually anecdotal, and the guides say so.

What the agent does

  1. Identify the provider from a name or URL: official domains, developer console, a search plan.
  2. Research with several targeted searches covering registration, scopes, review, partner programs and real-world timelines. Official docs are ranked first.
  3. Read each page and extract only facts it states, each with a short supporting phrase so a reviewer can find it.
  4. Probe live while reading: OAuth/OIDC discovery metadata, the developer console (is it behind a login?), Composio's toolkit page, and the real authorize endpoint called with a fake client ID and Composio's redirect URI.
  5. Write the guide from the extracted facts and probe results only.
  6. Verify with a separate pass that checks each claim against its sources, downgrades anything overclaimed and records corrections. Then code-level guards remove citations to pages the agent never read.

Where an agent stops

Signing in to a developer console, accepting terms, verifying a domain in DNS, paying for a security assessment, recording a demo video and signing partner agreements need a person with the account. The guides mark these steps "You do this" and give you everything the agent could prepare: field values, redirect URIs, scope lists and justification text.

Limits

  • Probes run without credentials, so they can prove an endpoint exists and how it treats unknown clients, but not that your app would be approved.
  • Some providers block automated requests. A blocked probe counts as no evidence and is shown as inconclusive.
  • Provider rules change. Each guide shows the date it was checked, and you can re-run the investigation at any time.
